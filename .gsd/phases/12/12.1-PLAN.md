# Plan 12.1: Interactive 360 Model Viewer

## Objective
Give visitors an interactive 3D model of the masterplan they can turn through a
full 360 degrees, zoom and explore, served from the site itself rather than a
third party embed, without changing anything about the existing homepage.

## Context
- Source asset: `3d Asset/Yamuna_Sky_City_2608-v1.glb` (untracked, 45.7 MB)
- New feature directory: `src/features/model-viewer/`
- New route: `src/app/explore/page.tsx`

## Source asset findings

Measured from the raw export before any work started.

| Property | Value |
|---|---|
| Size | 45.7 MB |
| Triangles | 2,326,741 |
| Vertices | 4,516,284 |
| Meshes / materials / textures | 363 / 166 / 124 |
| Texture resolution | already capped at 1024px |
| GPU texture memory | ~182 MB |
| Compression | Draco geometry, WebP textures |
| Animations / cameras | none |
| Origin | SketchUp; unnamed geometry (`3DGeom-1176`), materials grouped by finish |

The earlier estimate of 400 to 500 MB of texture memory was wrong. The textures
were already capped at 1024px, so the real figure is about 182 MB.

## Verification

| Check | Result |
|---|---|
| `npx tsc --noEmit` | clean |
| `npx next build` | passes, `/` and `/explore` both static |
| Model load, localhost | 2.7 to 3.9 s |
| Frame rate, Intel Iris Xe | 52 to 60 fps while auto rotating |
| Idle cost when still | no frames drawn |
| Mobile horizontal overflow | 0 px at 390px wide |
| Playwright, webgl project | see 12.1 results |

Headless Chromium defaults to SwiftShader, a software renderer that draws this
model at about 4 fps, which is slow enough that clicks time out. The `webgl`
Playwright project passes flags that hand the browser the real GPU.

## Known limitations

- **Hotspots are placeholders.** The export has no named geometry, so nothing
  identifies which mesh is which building. Positions must be set by someone who
  can see the model, using the placement tool at `/explore?place`.
- **Automatic framing is a heuristic.** Meshes are grouped by material rather
  than by building, and the scene holds tall, wide, paper-thin planes. Both
  pull the framing box wider than the towers. `FOCUS_OVERRIDE` in config.ts
  pins the composition when that matters.
- **Per-building selection is not possible** without renaming geometry in
  SketchUp and re-exporting.

## Pre-existing issues found, not fixed

- The homepage has no `<h1>`. Three of the five tests in `tests/homepage.spec.ts`
  already failed on this branch before any of this work, because they assert
  against markup the continuous-scroll rebuild replaced.
